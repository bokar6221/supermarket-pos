# نظام كاشير وإدارة محل — Android أولًا

تطبيق كاشير عربي RTL للمحلات الصغيرة والمتوسطة. واجهة البيع مبنية للهواتف، مع تطبيق Android أصلي يضم ماسح باركود باستخدام CameraX وGoogle ML Kit.

## الموجود في فرع التطوير الحالي

- بيع وفواتير وسلة وخصومات وطرق دفع نقدي/إلكتروني/آجل.
- إدارة منتجات وباركود وتصنيفات ووحدات قطعة/كيلو/جرام.
- ماسح Android أصلي عبر CameraX + ML Kit، مع فلاش وتركيز تلقائي وقراءة صيغ باركود متعددة.
- حفظ محلي باستخدام IndexedDB داخل Android WebView.
- سجل فواتير، ونسخ احتياطي JSON واستعادة.
- بيانات المحل (اسم/هاتف/عنوان/عبارة الفاتورة) وإعداد عرض 58mm/80mm/A4.
- حفظ اسم العميل ورقم هاتفه اختياريًا مع الفاتورة.
- معاينة فاتورة، مشاركة نصها عبر قائمة المشاركة في Android، وفتح واجهة الطباعة الأصلية.

## الحالة والحدود

هذا الفرع بداية تطوير تجاري وليس إصدارًا نهائيًا تم اختباره ميدانيًا. واجهة الطباعة تستدعي Android Print Framework؛ توافق الطابعات الحرارية يتوقف على الطابعة وخدمة الطباعة المثبتة ويجب اختباره فعليًا. المشاركة الحالية ترسل تفاصيل الفاتورة كنص، وليست PDF مرفقًا.

قاعدة البيانات محلية لكل جهاز في الوقت الحالي. لا توجد بعد مزامنة بين الأجهزة أو فروع، ولا تسجيل دخول أو صلاحيات أو مشتريات وموردون أو مرتجعات أو خزينة وورديات أو وحدة صيدلية/ذهب مكتملة. لا تعتبر النسخ الاحتياطي مزامنة.

التطبيق ليس نظام إيصال ضريبي/فاتورة إلكترونية معتمدة حتى يتم استكمال التكامل والمتطلبات الرسمية.

## التشغيل والبناء

- مشروع Android: android-app/
- ملف نقطة الدخول: android-app/app/src/main/java/com/supermarket/pos/MainActivity.java
- ملفات الواجهة الأساسية في جذر المستودع، ويقوم GitHub Actions بنسخها إلى android-app/app/src/main/assets/www/ قبل البناء.
- Workflow البناء: .github/workflows/build-android-apk.yml

## سلامة البيانات

- لا تضع نسخًا احتياطية حقيقية للمحل داخل GitHub.
- احتفظ بنسخ احتياطية خارج الهاتف واختبر الاستعادة قبل الاستخدام التجاري.
- عند إضافة جداول أو حقول هيكلية مستقبلًا، استخدم ترحيلات قاعدة بيانات متوافقة ولا تستبدل بيانات المستخدمين.
- كل فاتورة محفوظة محليًا على الجهاز الذي أنشأها حتى تنفيذ المزامنة.
