# مراجعة جاهزية الإصدار التجاري — POS 1.10.0

تاريخ المراجعة: 2026-11-13
فرع المراجعة: `license-device-management-v1`
الفرع المستهدف: `offline-first-rebuild-v2`

## الخلاصة التنفيذية

المشروع يحتوي على وظائف تشغيلية حقيقية للبيع والمخزون والمشتريات والعملاء والمرتجعات والخزينة والورديات والتقارير والنسخ الاحتياطي المحلي والمزامنة السحابية والتراخيص. لكنه **ليس معتمدًا تجاريًا بعد**؛ فهناك مخاطر تشغيل ومزامنة تحتاج اختبارًا ميدانيًا، كما أن نشر Firebase وإعداد مفتاح توقيع Release لم يكتمل.

## ما تمت مراجعته وإصلاحه في هذه الجولة

| المجال | النتيجة |
|---|---|
| البيع والفواتير | منطق حفظ الفاتورة يتحقق من البنود والإجمالي والخصم والكمية والمخزون، والاختبارات تغطي البيع والمرتجعات والخصم |
| المرتجعات | منع تكرار بند المرتجع أو تجاوز الكمية المتبقية، وتوزيع الخصم والتقريب على المرتجعات الجزئية |
| المشتريات | اكتُشف أن طبقة قاعدة البيانات لا تتحقق من تطابق إجمالي الفاتورة مع مجموع (الكمية × تكلفة الوحدة)، ولا تمنع القيم اللانهائية أو طريقة دفع غير معتمدة؛ تم إصلاح ذلك وإضافة اختبارات |
| صلاحيات الكاشير | اكتُشف السماح بكتابة حركات خزينة مباشرة من دور الكاشير رغم عدم مزامنة سجل الخزينة لهذا الدور؛ أزيلت الصلاحية من قواعد Firestore |
| الوضع المحلي | اكتُشفت مشكلة في اكتشاف جلسة المالك المحلي وتحديث عرض الصلاحيات بعد استيراد الترخيص؛ تم إصلاح التعرف على الجلسة وتحديث واجهة الأدوار |
| التراخيص والأجهزة | تمت مراجعة تدفق إصدار الترخيص وتوقيعه وتسجيل الأجهزة وخاناتها وإلغاء الربط وقواعد Firestore؛ ما زال يلزم اختبار القواعد على Firebase Emulator/مشروع اختبار |
| Android Release | أضيف إعداد توقيع Release من متغيرات البيئة، وWorkflow مستقل لبناء APK موقّع والتحقق من الحزمة والتوقيع |

## الوظائف الموجودة في المشروع

- كاشير وبيع نقدي وإلكتروني وآجل، وخصومات وفواتير.
- منتجات وباركود وتصنيفات ووحدات قطعة/كيلو/جرام.
- حركات مخزون، تنبيهات حد الطلب، تسويات وجرد فعلي.
- مشتريات وموردون ومدفوعات وأرصدة.
- عملاء ومديونيات وتحصيلات وكشوف حساب.
- مرتجعات جزئية وكلية مرتبطة بالفاتورة.
- خزينة وورديات وتقارير مالية وتشغيلية.
- نسخ احتياطي واستعادة محليان.
- مزامنة Firestore وأدوار موظفين.
- تراخيص محلية وسحابية، مدد مختلفة، وحد أجهزة وإلغاء ربط.

وجود الوظيفة في الكود لا يعني اجتياز اختبار قبول ميداني لها.

## مخاطر مانعة لاعتماد الإصدار التجاري

### 1. المزامنة متعددة الأجهزة
- عند تعديل السجل محليًا وسحابيًا في الوقت نفسه، النظام يسجل تعارضًا ولا يحله تلقائيًا.
- بيع جهازين دون اتصال على نفس المخزون قد يؤدي إلى رصيد سالب بعد المزامنة.
- يلزم تحديد سياسة تعارض واضحة واختبار البيع المتزامن والاستعادة وتبديل الأدوار على جهازين أو أكثر.

### 2. التراخيص والحماية
- قواعد Firestore الجديدة موجودة في الفرع ولم تُنشر إلى Firebase الحقيقي.
- لا توجد حتى الآن نتيجة اختبار Firebase Emulator موثقة لقواعد الأجهزة والصلاحيات.
- الترخيص المحلي الموقّع ليس مرتبطًا ببصمة عتادية؛ يمكن نسخ الملف إلى جهاز آخر.
- إلغاء جهاز أو تعليق ترخيص لا يصل إلى جهاز مفصول عن الإنترنت حتى يعود الاتصال.
- التحقق دون اتصال يعتمد على ساعة الجهاز؛ لذلك لا يمثل حماية DRM مطلقة.

### 3. الاعتمادية والنسخ الاحتياطي
- النسخ الاحتياطي المحلي يحتاج اختبار تصدير واستعادة فعليًا على أجهزة مختلفة، مع إثبات عدم فقد البيانات.
- يلزم اختبار امتلاء مساحة التخزين، إغلاق التطبيق أثناء الحفظ، وإعادة تشغيل الهاتف بعد عمليات البيع.
- لا يوجد حتى الآن اختبار آلي شامل لترحيل قواعد بيانات جميع الإصدارات السابقة.

### 4. الأجهزة والطباعة
- الماسح الأصلي يستخدم CameraX وML Kit، لكن يلزم اختبار سرعة ودقة القراءة على أجهزة Android المستهدفة.
- الطباعة عبر Android Print Framework موجودة، لكن الطباعة الحرارية ومقاسات الورق والاتصال بالطابعات لم تُعتمد باختبار ميداني.
- مشاركة الفاتورة وواتساب تحتاج اختبارًا على نسخ Android وتطبيقات مختلفة.

### 5. النطاق التجاري
- تتبع صلاحية/تشغيلة المنتجات غير مثبت ضمن الوظائف الحالية.
- التكامل مع الفاتورة الإلكترونية/الإيصال الضريبي المصري غير منفذ أو معتمد.
- تقارير الربح تظل تقديرية عندما تكون تكلفة بعض الأصناف أو الفواتير التاريخية غير معروفة.
- حصة Firebase Spark مشتركة على مستوى مشروع Firebase؛ يجب مراقبة حدود الاستخدام وتحديد خطة تشغيل العملاء قبل التوسع.

## حالة الاختبارات

- يوجد Workflow سابق نجح في فحص JavaScript، وفحص سلامة الواجهة والبيانات، وبناء APK Debug والتحقق من توقيعه.
- أضيفت في هذه المراجعة اختبارات شراء للتحقق من تطابق الإجمالي والتكلفة المرجحة وحركة الخزينة.
- أضيفت اختبارات ثابتة لصلاحية الكاشير وحالة المالك المحلي.
- **لم يتم بعد تأكيد نجاح CI على أحدث commit بعد هذه الإصلاحات.**
- لا يوجد حتى الآن تقرير اختبار Firebase Emulator أو تقرير اختبار أجهزة/طابعات حقيقية.

## بوابة إصدار Release التجاري

تم تجهيز:
- Gradle Release signing عبر متغيرات بيئة محمية.
- Workflow: `.github/workflows/build-android-release.yml`.
- دليل إعداد المفتاح: `docs/ANDROID_RELEASE_SIGNING_AR.md`.

ما زال مطلوبًا من مالك المستودع إنشاء مفتاح JKS نهائي وحفظه بأمان وإضافة الأسرار الأربعة إلى GitHub Actions Secrets. لا ينبغي إرسال المفتاح أو كلمات المرور داخل المحادثة أو المستودع.

## شروط اعتماد النسخة التجارية

1. نجاح CI على أحدث commit.
2. اختبار قواعد Firestore على Emulator أو Firebase staging، بما يشمل تجاوز حد الأجهزة، إلغاء الربط، الأدوار، وفصل بيانات المحلات.
3. اختبار سيناريوهات البيع والشراء والمرتجعات والخزينة والورديات والاستعادة على أجهزة فعلية.
4. اختبار مزامنة جهازين أونلاين، ثم أوفلاين، ثم عودة الاتصال وحل التعارض.
5. اختبار ماسح الباركود والطباعة الحرارية على الأجهزة المستهدفة.
6. إعداد مفتاح Release الدائم وحفظ أسراره.
7. بناء APK Release موقّع والتحقق من توقيعه وتثبيته وتحديثه.
8. موافقة المالك قبل دمج التغييرات ونشر قواعد Firebase.

**قرار المراجعة:** جاهز لمواصلة الإصلاح والاختبار، غير جاهز بعد للتوزيع التجاري النهائي.
