# Cashiro — مرشح الإصدار التجاري 1.13.0

## نطاق هذا الفرع
هذا الفرع مستقل عن `main` وعن فروع العمل السابقة. لا يدمج أي تغييرات في الفرع الأساسي ولا ينشر قواعد Firebase إلى المشروع الحقيقي تلقائيًا.

- الاسم التجاري: Cashiro.
- Android package: `com.supermarket.pos` (محافظ عليه للسماح بتحديث التطبيق مستقبلًا بنفس هوية الحزمة).
- الإصدار: `1.13.0`، ورقم البناء `17`.
- واجهة الفاتورة تقبل تعديل كمية كل صنف من حقل رقمي مباشر بدل أزرار الزيادة والنقصان.
- تسجل الفاتورة المبلغ المدفوع فعليًا، وتحسب الباقي تلقائيًا. يُسجل المدفوع في الخزينة فقط، ويضاف الباقي إلى مديونية العميل عند وجود مبلغ مستحق.
- تم تحديث إيصال الطباعة والمشاركة ليعرض المطلوب والمدفوع والباقي.
- عند المرتجع الجزئي تُخفض المديونية الفعلية أولًا بعد احتساب التحصيلات السابقة؛ وأي مبلغ يتجاوز الدين المتبقي يُسجل كقيمة مردودة نقدًا أو إلكترونيًا بالطريقة المختارة. لا يُخصم إجمالي المرتجع من الخزينة تلقائيًا.
- `compileSdk 36` و`targetSdk 36`، مع معالجة edge-to-edge في MainActivity.
- التوزيع المستهدف: APK مباشر. لا يتضمن هذا المسار إعداد Google Play.

## التغييرات المضافة في المرشح
1. اسم التطبيق في Android وواجهة الويب وPWA هو Cashiro.
2. أيقونة Android وPWA ورأس واجهة الويب تستخدم هوية Cashiro الخضراء/الفحمية، مع أشكال زخرفية متناسقة للواجهة.
3. تم تعطيل Android Auto Backup لتقليل انتقال بيانات المحل الحساسة تلقائيًا بين الأجهزة. يظل النسخ الاحتياطي اليدوي JSON متاحًا من التطبيق.
4. زر «تسجيل الخروج» ينهي جلسة Firebase ويمسح جلسة الدور المحفوظة ويقفل الوصول المحلي، لكنه لا يحذف قاعدة بيانات المحل من الجهاز.
5. أضيفت صفحة `privacy.html` مدمجة داخل التطبيق، وزر «طلب حذف الحساب».
6. ينشئ زر الحذف مستندًا في `accountDeletionRequests/{uid}` بقواعد Firestore محددة. **هذا طلب مراجعة وليس حذفًا فوريًا أو آليًا.** تتم المعالجة يدويًا بعد التحقق، خصوصًا لمالك المحل حتى لا تضيع ملكية المحل أو السجلات المالية. يجب توضيح سياسة الاحتفاظ القانونية لصاحب المحل.
7. أضيفت اختبارات Emulator لقواعد طلب الحذف، مع منع قراءة طلبات مستخدم آخر أو إنشائها باسم مستخدم آخر.

## إعداد Firebase المطلوب
تم تجهيز الملف الجديد `firestore.rules` في هذا الفرع. لأن قواعد Firebase التي نُشرت للإصدار 1.11.0 لا تتضمن `accountDeletionRequests`، يجب على مالك المشروع مراجعة الملف كاملًا ثم نشره يدويًا في Firebase Console قبل اختبار زر طلب الحذف. لا تُحذف أي مجموعات حالية ولا تُستبدل بيانات المستخدمين أو المحلات.

اختبارات Firestore Emulator في GitHub Actions نجحت في تشغيل 20 نوفمبر 2026 على قواعد هذا الفرع. هذه نتيجة اختبار للمحاكي وليست نشرًا لقواعد Firebase الحقيقية.

## قرار الحالة
هذا الفرع **مرشح تجاري مهيأ للبناء والاختبار** وليس بعد APK Release معتمدًا. توقيع النشر الدائم والاختبارات الميدانية ومعالجة طلبات حذف الحساب تظل بوابات إلزامية قبل البيع العام.

## معالجة طلبات حذف الحساب
بعد نشر قواعد Firestore الجديدة:
1. تظهر الطلبات داخل Firestore Database → Data → مجموعة `accountDeletionRequests`، والمستند يحمل UID صاحب الطلب.
2. تحقق من البريد وUID واسم المحل والدور قبل اتخاذ أي إجراء.
3. للموظف: أزل عضويته من `shops/{shopId}/members/{uid}` وملف `users/{uid}` بعد التحقق من صاحب الطلب، ثم احذف حساب المصادقة من Authentication → Users. لا تحذف فواتير المحل أو سجلاته المشتركة لمجرد حذف موظف.
4. لصاحب المحل: لا تحذف حساب المصادقة أو ملف المحل قبل نقل الملكية أو إغلاق المحل، وتصدير السجلات وحسم الاحتفاظ القانوني بها. تتم معالجة طلب المالك يدويًا مع مالك المشروع.
5. بعد إتمام المراجعة، احذف مستند الطلب من Firestore Console لتسمح بطلب جديد إذا لزم الأمر.

هذه النسخة تسجل طلب الحذف ولا تنفذ حذفًا تلقائيًا أو متسلسلًا من داخل التطبيق؛ لا ينبغي وصف الزر للمستخدم على أنه حذف فوري.
