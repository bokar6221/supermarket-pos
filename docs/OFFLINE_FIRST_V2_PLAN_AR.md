# خطة إعادة بناء الإصدار: Offline-first v2

## الهدف
إصدار جديد من برنامج كاشير المحل يبدأ ويعمل محليًا من أول تثبيت، ولا يجعل فشل Firebase أو غياب الإنترنت سببًا لإغلاق الواجهة أو منع البيع المحلي. تتم إضافة الحساب والمزامنة والترخيص كطبقات مستقلة فوق قاعدة البيانات المحلية.

## قواعد لا يجوز كسرها
1. لا تُحذف قاعدة IndexedDB ولا تُمسح بيانات المنتجات أو الفواتير عند فشل تسجيل الدخول أو الربط أو المزامنة.
2. تشغيل البرنامج محليًا لا يتطلب حساب Firebase ولا ترخيصًا سحابيًا. إنشاء حساب وربط محل سحابي اختيار اختياري.
3. لا يُنشأ محل سحابي تلقائيًا بمجرد تسجيل الدخول. يجب أن يختار المستخدم صراحةً: ربط محل موجود، إنشاء محل جديد، أو تخطي الربط والاستمرار محليًا.
4. كل عمليات البيع والحفظ والبحث والباركود والنسخ الاحتياطي تعمل محليًا. الإنترنت مطلوب فقط للمزامنة والتحقق/تحديث سياسة الترخيص.
5. لا تُطلب صلاحية الكاميرا عند فتح التطبيق؛ تُطلب فقط عند ضغط المستخدم على زر مسح الباركود. ولا تُطلب صلاحية ملفات عامة؛ يُستخدم Android Storage Access Framework عند الاستيراد/التصدير.
6. أخطاء الشبكة والصلاحيات السحابية تظهر كتنبيه قابل للإغلاق، لا كشاشة تقفل البرنامج.

## فصل الطبقات
- Local POS: IndexedDB محلي، يعمل دائمًا.
- Cloud Sync: تسجيل دخول اختياري، ربط/إنشاء المحل بموافقة صريحة، مزامنة في الخلفية، طابور تغييرات محلي، إعادة المحاولة عند عودة الشبكة.
- License & Offline Policy: ملف سياسة موقّع رقميًا ومخزّن محليًا. لا يُقبل تغيير السياسة من العميل دون توقيع إدارة المنصة.
- Platform Admin: إدارة الترخيص وسياسة Offline بصورة منفصلة عن حساب صاحب المحل.

## التحكم المطلوب للأدمن
لكل محل:
- السماح/منع العمل دون إنترنت (offlineAllowed).
- مدة السماح دون اتصال بعد آخر تحقق ناجح (offlineGraceHours أو offlineGraceDays).
- السماح بالمزامنة السحابية أو إيقافها (cloudSyncEnabled).
- حالة الترخيص: فعال/معلق/منتهي.
- وقت آخر تحقق ناجح وآخر مزامنة، وسبب منع المزامنة.
- عند إيقاف Offline من الأدمن، يسري القرار على الأجهزة عند أول اتصال لاحق واستلام السياسة الموقعة. لا يمكن لجهاز مفصول تمامًا عن الإنترنت استقبال أمر فوري؛ يجب توضيح ذلك في لوحة الأدمن.

## إصلاح تدفق الحساب
- عند تسجيل الدخول، لا يُنشأ محل تلقائيًا إذا لم يوجد users/{uid}.activeShopId.
- تظهر اختيارات صريحة: ربط بمحل قائم (دعوة/رمز مالك)، إنشاء محل جديد، أو متابعة محليًا.
- ربط محل قائم يتحقق من shop + membership + license قبل تغيير حالة الجهاز.
- تُنفّذ العملية على مرحلتين: تحقق أولًا، ثم تثبيت الربط بعد نجاح جميع الفحوصات.
- فشل الربط يعيد المستخدم إلى الوضع المحلي ولا يضع شاشة قفل فوق قاعدة البيانات المحلية.
- لا يعتمد إنشاء المالك أو تغيير ملكية المحل على تعديل يدوي عشوائي للمستندات؛ تُستخدم عملية إدارية موثوقة أو دعوة مالك واضحة.

## اختبارات قبول إلزامية
1. تثبيت نظيف مع وضع الطيران: تفتح الواجهة ويعمل البيع والمنتجات والنسخ الاحتياطي.
2. فتح التطبيق دون منح إذن الكاميرا: لا ينهار التطبيق ولا تظهر نافذة إذن؛ يظهر الإذن فقط بعد طلب المسح.
3. إيقاف الإنترنت أثناء البيع: تحفظ الفاتورة محليًا وتبقى ظاهرة بعد إغلاق التطبيق وفتحه.
4. تسجيل دخول ببريد لا يملك محلًا: لا ينشأ محل تلقائيًا ولا تضيع البيانات.
5. ربط UID غير عضو أو shopId غير موجود: تظهر رسالة مفهومة، ويظل الوضع المحلي سليمًا.
6. فشل Firestore أو انتهاء المهلة: لا يغلق التطبيق ولا يمنع الحفظ المحلي.
7. عودة الإنترنت: تتم المزامنة دون تكرار الفواتير أو الكتابة فوق تغييرات متعارضة.
8. تعطيل Offline من الأدمن: يُطبّق عند وصول السياسة الجديدة الموقعة، مع اختبار فترة السماح المحددة.
9. تغيير المستخدم/الدور: لا تُعرض بيانات دور سابق دون تأكيد ونسخة احتياطية، ولا تُحذف بيانات محلية بصمت.
10. اختبار APK على Android حقيقي قبل إعلان نجاح الإصدار.

## حدود الأمان
لا يمكن فرض إيقاف فوري على جهاز غير متصل كليًا. أقصى ما يمكن ضمانه هو تطبيق آخر سياسة موقعة عند الاتصال، ثم تطبيق حد السماح Offline المحفوظ محليًا. يجب ألا تعتمد الحماية على ساعة الجهاز وحدها دون توضيح هذا القيد.

## سياسة الإصدار
- التطوير على فرع مستقل، وعدم دمجه في main أو استبدال APK الحالي قبل نجاح الاختبارات.
- رفع APK تجريبي مستقل مع رقم إصدار جديد، وترك بيانات التطبيق الحالي دون مسح.
- لا يُعلن الإصدار جاهزًا قبل نجاح اختبارات البناء والتثبيت والتشغيل Offline والربط والمزامنة.
