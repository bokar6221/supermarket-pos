# إعداد التجربة المجانية وتسجيل الدخول والصلاحيات

هذا المستند خاص بالفرع `commercial-trial-auth-ux-v1`. الإصدار الحالي لا ينشر قواعد Firebase تلقائيًا ولا ينشئ APK نهائيًا.

## 1. إعداد Firebase مرة واحدة

في Firebase Console للمشروع `supermarketpos-e448a`:

1. افتح Authentication ثم Sign-in method.
2. فعّل **Email/Password** لحسابات أصحاب المحلات والموظفين ومدير المنصة.
3. فعّل **Anonymous** حتى يستطيع التثبيت الجديد بدء تجربة الجهاز تلقائيًا قبل إنشاء حساب بريد.
4. افتح Firestore Database ثم Rules، واستبدل محتوى القواعد بالكامل بملف `firestore.rules` من هذا الفرع فقط، ثم راجعه وانشره.
5. لا تلصق عدة نسخ متتابعة من قواعد Firestore. يجب أن يحتوي الملف المنشور على تعريف واحد فقط لـ `rules_version = '2'` وتعريف واحد لـ `service cloud.firestore`.

يمكن النشر باستخدام Firebase CLI بعد التأكد من المشروع النشط:
```bash
firebase use supermarketpos-e448a
firebase deploy --only firestore:rules
```

لا يتم نشر القواعد بمجرد رفع الكود إلى GitHub؛ النشر إلى Firebase خطوة مستقلة.

## 2. آلية التجربة المجانية

- عند أول فتح للتطبيق على جهاز جديد، يحاول التطبيق إنشاء جلسة Firebase Anonymous تلقائيًا.
- ينشأ مستند واحد في `deviceTrials/{deviceId}`، ويكتب وقت البداية بواسطة `serverTimestamp()` من Firebase، وعدد الأيام ثابت 7.
- على Android يستخدم التطبيق بصمة SHA-256 مشتقة محليًا من Android ID واسم الحزمة؛ لا يرسل Android ID الخام إلى Firebase.
- لا يمكن للتطبيق تعديل أو حذف سجل التجربة أو تمديده. التعديل الإداري فقط لحساب مدير المنصة.
- يتطلب بدء التجربة أول مرة اتصالًا بالإنترنت لتسجيل بدايتها على الخادم. بعد نجاح التفعيل، البيع المحلي يعمل دون إنترنت حتى انتهاء السبعة أيام.
- عند التسجيل بالبريد من داخل التجربة، يربط التطبيق البريد وكلمة المرور بحساب Anonymous الحالي باستخدام `linkWithCredential`، وبذلك يحتفظ بمعرّف UID نفسه وسجل التجربة.
- بعد انتهاء التجربة، يلزم ترخيص ساري من مدير المنصة لفتح التشغيل.
- في المتصفح العادي يستخدم التطبيق معرّفًا احتياطيًا من التخزين المحلي؛ مسح بيانات المتصفح قد يغيّره. بصمة APK على Android أقوى، لكنها ليست حماية مطلقة من إعادة ضبط المصنع أو العبث المتقدم بالجهاز.

## 3. فصل الحسابات

يوجد مساران منفصلان:

### مدير المنصة

مستند `platformAdmins/{uid}` ويجب أن يحتوي:
- `active`: Boolean = `true`
- `role`: String = `platform_admin`

يتم إنشاؤه يدويًا من Firebase Console. مدير المنصة يدير المحلات والتراخيص وحد الأجهزة، ولا يرث صلاحيات صاحب المحل ولا يقرأ سجلات المبيعات والعملاء.

### مستخدمو المحل

يتم تخزين دور المستخدم داخل `shops/{shopId}/members/{uid}`، والقيم المعتمدة أربع:
- `owner`: صاحب المحل.
- `manager`: مدير المحل، دون إعدادات المنصة الخاصة.
- `cashier`: كاشير.
- `accountant`: محاسب.

لا تضع `platform_admin` ضمن أدوار الموظفين، ولا تمنح الدور من شاشة المحل.

## 4. سلوك تسجيل الدخول وحالات الحساب

- جلسة Firebase تستخدم Local Persistence حتى لا تختفي بعد إغلاق شاشة التطبيق أو إعادة فتحه.
- فشل الشبكة لا يعني حذف الحساب أو تسجيل الخروج؛ تظهر رسالة اتصال واضحة وزر إعادة المحاولة.
- إذا أوقف صاحب المحل عضوية الموظف، يبقى حساب Firebase مسجلًا وتظهر حالة «العضوية غير نشطة» بدل تسجيل خروج إجباري.
- إذا لم يوجد ترخيص أو انتهت صلاحيته، تبقى حالة الحساب ظاهرة مع سبب الإيقاف، ولا يتم مسح بيانات المحل.
- لا يتم تجاوز حالة الترخيص أو العضوية باستخدام التجربة المجانية. التجربة تسمح لصاحب المحل فقط؛ الموظف يحتاج عضوية فعالة وترخيص المحل.
- تسجيل الخروج من المستخدم نفسه يظل متاحًا، ولا يبدأ تجربة مجهولة جديدة تلقائيًا بعد تسجيل الخروج.

## 5. مصفوفة صلاحيات المحل

| الدور | القراءة | الكتابة |
|---|---|---|
| صاحب المحل | جميع سجلات المحل بما فيها الإعدادات | جميع سجلات المحل |
| المدير | جميع السجلات عدا الإعدادات | السجلات التشغيلية والمالية عدا الإعدادات |
| الكاشير | المنتجات والفواتير والحركات والعملاء | المنتجات والفواتير والحركات والعملاء |
| المحاسب | المنتجات والفواتير والحركات والموردين والمشتريات والمدفوعات والعملاء والمرتجعات والخزينة والورديات والجرد | السجلات المالية والتشغيلية المحددة في القواعد |

تُطبق الصلاحيات في Firestore Rules وكذلك داخل واجهة التطبيق. إخفاء زر في الشاشة وحده لا يعد حماية.

## 6. الاختبار قبل الاعتماد التجاري

يجب اختبار الحالات التالية على جهاز Android فعلي:
1. تثبيت نظيف مع اتصال الإنترنت: تبدأ التجربة ويظهر وقت الانتهاء.
2. إغلاق التطبيق وفتحه وإعادة تشغيل الهاتف: تبقى الجلسة والتجربة.
3. فصل الإنترنت بعد بدء التجربة: يستمر البيع المحلي خلال المدة المتبقية.
4. ربط التجربة ببريد وكلمة مرور: يبقى UID وسجل التجربة كما هما.
5. انتهاء الأيام السبعة: تظهر شاشة الانتهاء ولا تُمسح بيانات المحل.
6. حساب مدير المنصة: تظهر إدارة المنصة فقط ولا تظهر سجلات المحل.
7. حساب كل دور من الأدوار الأربعة: تُختبر القراءة والكتابة المسموح بها والمرفوضة.
8. إيقاف عضوية موظف أو ترخيص جهاز: تظهر حالة واضحة دون تسجيل خروج بسبب لقطة Firestore مؤقتة من الذاكرة المؤقتة.

اختبارات قواعد Firestore في `tests/firestore-rules.test.mjs` تغطي الأدوار، منع مدير المنصة من سجلات المحل، وإنشاء التجربة مرة واحدة ومنع تمديدها من العميل. يجب تشغيلها على Firebase Emulator قبل نشر القواعد.
